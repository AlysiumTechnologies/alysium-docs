<span id="how-to-get-started" />

Build a small assistant for a fictional café, give it a short reference note and check its replies. Then add a greeting and choose its visitor appearance. You can keep the finished agent as a saved draft or share it with a generated link.

An **agent** is the assistant. Its **instructions** describe its job and behavior; its **knowledge** supplies reference facts. A **space** holds your agents, files and plan. AI-assisted drafting and preview conversations use that space's credits.

<span id="start-where-you-are" />

## Create the practice agent

Open [Home](https://app.alysium.ai/spaces) and select **Create New Agent**. Enter this description:

> Create a friendly assistant for a practice café. Answer visitors' questions using the café FAQ that I will add. Keep answers short and clear. If the FAQ does not include the answer, say so and suggest speaking to a café team member at the counter. Do not invent opening hours or claim to make bookings.

Select **Draft my agent**. Alysium creates the agent and opens its builder with a drafted name, instructions, greeting and suggested questions. You will add the actual FAQ separately.

If you prefer to write the setup yourself, find **or pick a starting point** below the description box. On the **Create Your AI Agent** blank-canvas card, select **Create Agent**. If you remain on Home after creation, open the new agent's card.

If you already created this practice agent, open it from Home and use that draft.

<span id="review-the-drafted-setup" />

## Review the setup

The builder opens in **Build**. Use its **Settings** view; if Profile or Chat Preview is showing, select Settings. On a phone, the main **Build**, **Design** and **Deploy** tabs are in the bottom dock.

1. Set **Agent Name** to **Practice café FAQ**.
2. Scroll to **Agent Builder** and read **Agent Instructions**. Correct invented café facts or promises to make bookings. If you started blank, enter these instructions:

   > Help visitors explore the practice café FAQ. Use its knowledge for café facts and keep answers short. If the FAQ does not answer a question, say so and direct the visitor to a café team member at the counter. Do not invent hours or make or change bookings.

3. Check **AI Models** in Agent Builder. The model produces the replies. If a model name is shown, you can keep it for the first test. If it says **Select a model...**, open the picker, browse the categories and choose an available model whose description fits the task. Check that its name appears in the selector.

The name and instructions save automatically. Wait for saving to finish before leaving; on a computer, the save indicator's tooltip can show **All changes saved**. Correct any displayed validation message. The separate [instruction helper](/build-your-agent/let-ai-draft-or-refine-your-instructions) can draft or refine instructions later; it is a different action from creating this agent.

## Add the practice facts

Scroll farther down in Settings to **Knowledge**. In **Paste Text**, enter this fictional note:

> Practice café FAQ — fictional learning example.
>
> The café serves coffee, tea and sandwiches.
>
> The entrance is step-free.
>
> For booking changes or questions the FAQ cannot answer, speak to a café team member at the counter. The chat assistant cannot make or change bookings.
>
> Opening hours are not included in this FAQ.

Select **Add as Document**, then wait for the note to show **Ready** in **Attached knowledge**.

This saves the note in Library and attaches it to this agent. Typing alone does not submit it, and you do not need to add the same note again in Library. If a warning says it was saved but not attached, select **Retry attachment** and check Attached knowledge again.

For a real café, replace the practice note with approved facts and a real contact route before offering the agent to customers.

## Set how the agent uses the note

The FAQ deliberately leaves out opening hours. Give the agent a useful response to that gap:

1. In Knowledge, open **Behavior** if it is collapsed.
2. Under **Answer grounding**, choose **Strict** to guide answers toward the supplied sources.
3. Turn on **Always consult knowledge before answering**.
4. In **When the answer isn't in my knowledge…**, enter:

   > The practice FAQ does not include that information. Please speak to a café team member at the counter.

Pause for the automatic save. Behavior has no separate Save button. These settings guide source use and the missing-answer reply; checking actual answers is still part of the work. You can [compare the other knowledge behavior choices](/knowledge-and-library/control-how-your-agent-uses-its-knowledge) for a different kind of assistant.

## Try the practice agent

Use the chat beside the settings on a wide screen. On a smaller screen, select **Chat Preview** within Build.

Enter each question separately and select **Send message** or press Enter. Each question contains the context the agent needs.

| Question | What to check in the reply |
|---|---|
| **What does the café serve?** | It should name coffee, tea and sandwiches. |
| **Is the café entrance step-free?** | It should match the note's accessibility information. |
| **What are the café's opening hours?** | It should acknowledge the missing information and give the café-counter contact route. |
| **Can you change my café booking?** | It should direct you to a café team member rather than claim to change a booking. |

If a reply misses a supplied fact, check that the note is attached to this agent and **Ready**. Then review the instructions and Behavior for a conflicting or missing rule. Save one correction and ask the same question again so you can compare the result. If the facts are right but the reply is too long, adjust the answer style in Agent Instructions.

You can [plan a broader set of preview checks](/build-your-agent/test-your-agent-while-you-build) as you develop your own agent.

## Add a visitor greeting and starter

Return to Build's **Settings** view. In **Welcome Message**, enter:

> Hi! I can help you explore our practice café FAQ. What would you like to know?

The greeting saves automatically. Correct any validation message and wait for saving to finish.

In **Suggested Conversation Starters**, use **Is the café entrance step-free?** as a question visitors can choose. Edit an existing starter, or select **Add prompt** and enter it in the new field. Click or tap outside the field to save the text.

Use **Remove prompt** on any drafted question that the note cannot answer or that promises an unsupported action. Adding and removing starters saves immediately; editing their text saves when you leave the field. The greeting and starters introduce the conversation; the instructions and knowledge still guide its answers.

## Choose the visitor appearance

These are choices for this practice project:

1. Open the main **Design** tab. On a smaller screen, use the **Design** subview for controls.
2. Under **Theme**, select **Change**, choose **Light**, then select **Done**.
3. Scroll to **Features**. Turn on **Starter prompts** and turn off **File upload**; visitors do not need to submit files for this FAQ.
4. Inspect the appearance beside the controls, or use the narrow-screen **Preview** subview.
5. Return to the Design controls, select **Save Changes** and wait for **All Changes Saved**.

The preview can show unsaved edits. **Done** closes the theme choices; **Save Changes** saves the Design changes. You can [explore other appearance choices](/design-your-widget/change-how-your-widget-looks) when you build an agent for your own audience.

## Make the practice purpose visible

Open **Build**, then **Profile**. In **Description**, enter:

> Fictional café FAQ created to learn Alysium. Its answers are practice information, not a real business's policies.

Wait for the automatic save. Keep the recognizable practice name so you can find the agent again.

## Make it live when you want to share

Making the agent live opens public access. You can keep this saved draft while you practice; take this step when you want others to use it and its content is suitable for them.

1. Open **Deploy** and read the launch card.
2. If **Finish in Build** names missing fields, return to Build's Settings, complete those fields and wait for their automatic save. Return to Deploy.
3. Select **Make agent live** and wait for **Live**.

This saves publication and public access together. Enabling the visitor link is a separate choice; a marketplace offer or website installation is also a separate task.

## Share the generated link

With the agent Live:

1. In Deploy, select **Share link + QR**.
2. Turn on **Direct link** if it is off. Wait for the setting to save and the generated URL to appear.
3. Select **Try your live agent**. Check that the intended practice agent opens in the new tab.
4. Return to Deploy and select **Copy** beside the URL. **Copied!** confirms the clipboard action; paste it where you want to share it.

Use the generated visitor link rather than the builder's address bar. If copying fails, select and copy the displayed URL manually. The [link and QR guide](/share-and-deploy/share-your-agent-with-a-link-and-qr-code) explains the other sharing choices. A [website widget](/share-and-deploy/put-your-agent-on-your-website) requires its own installation on your site.

## Check your finished project

Return to [Home](https://app.alysium.ai/spaces) and reopen the same agent. Check that its name and instructions remain, the note is attached and Ready, and Knowledge's Behavior retains your choices. Reopen Design to check the saved appearance.

You now have a saved practice agent with instructions, reference facts and replies you can compare with the note. If you chose to share it, also check the generated link's visitor destination.

## If a step fails

- **Drafting credits are unavailable:** use the blank starting-point card and enter the setup yourself. Preview messages still use credits.
- **Creation reports an error:** read the result before retrying. If the agent was created but its builder did not open, find that agent on Home and open its card.
- **Pasting reports an error:** correct the displayed problem before submitting again. If saving succeeded but attachment failed, use **Retry attachment** rather than submitting another copy of the note.
- **A usage notice stops preview:** check the affected space's [Billing](https://app.alysium.ai/spaces?settings=billing) and [the matching usage message](/help/billing-and-usage-messages).
- **A deployment setting fails to save:** read the result and use **Retry** if offered. Recheck **Live** and the saved **Direct link** setting before sharing the URL.

For a problem you cannot resolve, email [support@alysium.ai](mailto:support@alysium.ai) with the agent's name, the step you tried and the exact result or message.
