Use an agent's **Feedback** tab to investigate a reported problem, decide what needs attention and record how you handled it.

Reports include negative answer ratings, **Not great** conversation check-ins and recorded answers that cut off. A check-in concerns the conversation overall. A reason or source reference helps you investigate; it does not establish what caused the problem.

## Open Feedback

1. Open [Analytics](https://app.alysium.ai/analytics) and select the intended agent under **Your Agents**.
2. Check the agent's name, then select **Feedback**.
3. Under **Needs attention**, select **Open** and choose a report.

On a small screen, **Back to problems** returns from the report to the list. Scroll inside that list to load older reports.

## Open a report

Use the list's controls to find the reports you want to review:

| Control | What it changes |
|---|---|
| **Open** / **Resolved** | Shows reports awaiting attention or reports marked as handled. |
| **Filter by date range** | Filters by when the report was recorded, using inclusive local calendar days. Open the calendar, select a start and end day, then check both dates. Choices apply immediately; click outside or press Escape to close it. **Clear Date Filter**, or the X labelled **Clear date filter**, removes the range. |
| **Reason** | Select one or more reasons to narrow the list. Choices apply immediately. **Clear reasons** removes the selection. |

The reasons include **Wrong information**, **Didn't answer my question**, **Missing details**, **Hard to understand**, **Slow or buggy**, **Feature request**, **Unsafe**, **Something else** and **No reason given**. **Cut off** appears only when the chosen range has relevant recorded evidence.

The Open and Resolved counts follow the report date range, without narrowing to selected reasons. The Feedback tab's badge counts all open reports across all time. Neither uses the header's **Period** as its date filter.

## Read the answer in context

Read the question, answer and pinned feedback together, including the visitor's note if one is present. Read **What to do** before choosing a change.

Expand **N earlier messages** or **N later messages** to read the surrounding exchange. **Previous rated answer** and **Next rated answer** move between rated answers in that conversation. You may reach a helpful answer, which shows its rating without repair or resolution controls.

An unread dot is separate from resolution. Deliberately selecting a report can mark it read; it does not mark the problem resolved.

Visitor notes are shared with the owning space and Alysium for private review under the existing access rules. They are not included in conversation exports.

### Check what the answer used

**Used for this answer** shows references stored with the answer. Select **Open** beside a reference to visit its stored website page or find a readable document in Library. The section is hidden when there are no stored references.

A document can show its current name and update information, which may postdate the answer. Compare the answer with the relevant source material and the surrounding question. These references do not provide a complete explanation of how the answer was produced or prove that a source was correct.

### Follow the repair guidance

Follow the report's **What to do** guidance. For an original agent you can edit, **Edit knowledge**, **Edit instructions** or **Edit max length** opens the corresponding builder area. An installed copy does not offer these edit buttons; follow the guidance shown for that report.

These buttons open a place to make a change. Complete that area's saving steps and check the result before treating the change as handled. If the issue concerns missing source material, you can [review how knowledge is attached](/knowledge-and-library/give-your-agent-knowledge). If the instructions need work, you can [revise what the agent is told to do](/build-your-agent/write-your-agents-instructions).

## Mark a report as resolved

After completing the appropriate change or follow-up:

1. Return to the report and read the scope beside **Mark resolved**. For a **Cut-off answer**, resolving it resolves all open cut-offs for this agent.
2. Select **Mark resolved** and wait for the state update.
3. Return to the list with **Back to problems** on a small screen, then select **Resolved**. Check that the report appears there.

The action saves the handling state without a separate Save button. It does not rewrite the recorded answer or establish that future answers will be correct.

## Reopen or recognize a withdrawn report

If a resolved report needs attention again and offers **Reopen**, select it, wait for the update and check that it returns to **Open**. A visible Reopen button can still be refused, including on a cut-off report. Follow the refreshed report and any error; a click alone does not confirm the change was saved.

A visitor can change or clear a negative vote, or change their check-in. That withdraws the report: it leaves the lists, and an already-open report shows the changed feedback without the repair and state controls. Follow that refreshed state rather than treating withdrawal as a resolution you saved.

## If reports are missing or a read fails

Clear an unintended reason or date filter, check both **Open** and **Resolved**, and scroll inside **Needs attention** for older reports. If **Load older problems** is offered, it loads the next older results.

Feedback records eligible ratings, sampled visitor check-ins and recorded cut-offs. It does not measure everyone's satisfaction, and older ranges can lack recorded evidence. An empty list or a missing **Cut off** reason does not establish that answers were correct. Your own builder preview and Analytics review do not offer visitor rating controls.

If the problem list, selected report or expanded messages fail to load, use the **Retry** beside that failed read. For a resolution or reopening error, read the refreshed report first. **Couldn't update this report. Try again.** means you should check its current state before trying the action again. **This report changed since you opened it.** means the refreshed feedback may no longer support the action. Confirm the resulting Open or Resolved state before treating your change as saved.
