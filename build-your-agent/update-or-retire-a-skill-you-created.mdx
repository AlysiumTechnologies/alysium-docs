Upload revised guidance to a skill your space created, or retire the skill when you want to stop offering it. Updating keeps the skill's identity; retirement removes it from your library and new discovery.

If you only want one agent to stop using a skill, turn off its switch in **Skills**. You can also open its details and select **Remove from agent** to detach it while keeping the library entry for reuse.

## Open your authored skill

1. Open [Home](https://app.alysium.ai/spaces) and select **Build** on the intended agent's card.
2. Select **Settings** if needed, then scroll to **Skills** in the **Agent Builder** section.
3. Open the attached skill's name. If it is not attached, select **Browse skill library**, then **My Skills**, and open it there.
4. Read the current **Version** and **SKILL.md** contents. Use the file list to read any supporting files you plan to change.

Your space's authored skills offer **Update** and **More actions** in their details. Acquiring another creator's skill lets you use it, while its original remains theirs to maintain.

## Upload a revised version

Edit the files in your saved bundle and keep a copy of the previous bundle for your own records. For example, you could change a customer-answer method to ask for missing details before drafting a reply.

Keep the same top-level folder and matching `name` in **SKILL.md**. Update does not rename a skill. The archive still needs **SKILL.md** directly inside that one folder, starting with `---`, its required `name` and nonempty `description`, and a closing `---` before the guidance. The name uses lowercase letters or numbers separated by single hyphens and has at most 64 characters; the description has at most 1,024 characters.

Create a revised `.zip` or `.skill` archive of the whole folder. It must be at most **5 MiB compressed** and **25 MiB unpacked**, with no more than **30 files**. These byte limits are 5,242,880 and 26,214,400 bytes respectively. You can [see a complete SKILL.md and packaging example](/build-your-agent/upload-your-own-skill) when preparing a new bundle.

Ordinary attachments to a skill authored by your space follow its current version. An update can therefore change the guidance used by other agents in your space. Uploading also attempts to attach and enable it on the agent currently open, even if you had removed or disabled it there.

1. In the skill's details, select **Update**. The uploader is labelled **Update “name”**.
2. Select **Browse bundles** and choose the revised archive. Selection starts the upload immediately.
3. Wait for uploading to finish. Correct any displayed validation message before trying again.
4. Open the skill's details and inspect **Version** and the revised contents. If they still show the previous version after upload finishes, reload Build and check them again.
5. Check the agent's attached row and enabled switch, then try a task matching the revised guidance in the chat beside Settings or in **Chat Preview**. Enter the task and select **Send message** or press Enter; preview messages use credits.

Alysium assigns the numbered versions, such as v1 and v2. A `metadata.version` value inside the bundle is only descriptive. Uploading identical archive bytes returns the existing version rather than creating another number. The skill's existing tags, visibility and price remain with it; this Update flow skips the tag step.

The upload saves the revision directly. If the skill is in **My Skills** but is missing from this agent, select **Browse skill library → My Skills** and use **Attach**, or open the skill and select **Attach to agent**. Check the enabled switch afterward. Check this state before repeating an upload after an error.

### Update a skill acquired from another creator

An acquired skill stays on the version accepted for that agent. When a newer version is available, its attached list row offers **Update**. This action immediately accepts the current published version for this agent; other agents' acquired attachments keep their accepted versions.

Opening the attached skill's details shows the version already accepted for this agent. After choosing the row's **Update**, wait for the action, inspect the resulting **Version** and contents, and test a relevant task. This changes the agent's attachment, rather than uploading a replacement to the creator's original skill.

## Retire the skill

Retirement removes the authored skill from your library and new discovery, and automatically detaches it from agents in your space. People in other spaces who already acquired it keep their access and attachments.

Retirement cannot be undone. Uploading the same name later creates a fresh skill rather than restoring this one. Keep any bundle you want to retain before deleting.

1. In the authored skill's details, open **More actions** and select **Delete skill**.
2. Read the inline confirmation. Select **Cancel** to keep the skill, or **Delete skill** again to retire it.
3. Wait for the request to finish and check that the skill is gone from the refreshed library and Skills list. The details close as soon as you confirm, so their closing alone does not establish completion.

If a deletion error appears, read it and check the library's current state before trying the action again.
