<span id="turn-widget-features-on-or-off" />

Choose whether visitors see starter questions, can attach files or can rate answers. These choices change the conversation experience; keeping copies of visitor files is a separate decision.

## Open the feature controls

Open [Home](https://app.alysium.ai/spaces), select **Build** on the intended agent's card, then open the main **Design** tab. Scroll to **Features** and **Conversation Management**.

On a smaller screen, use the **Design** subtab for controls and **Preview** to inspect the widget.

## Choose the conversation features

| Switch | When to use it |
|---|---|
| **Starter prompts** | Show the opening questions you have written for the agent. Turn it off for an opening without those questions. |
| **File upload** | Let visitors attach material to a website widget conversation. Useful when the agent's job involves a visitor's own document or image. |
| **Answer feedback** | Let visitors rate eligible answers and provide comments where offered. This setting also applies to the separate chat-link experience. |

Write the questions in **Build → Settings**, under **Suggested Conversation Starters**. The Starter prompts switch controls their display. You can [edit the greeting and starter questions](/build-your-agent/set-a-welcome-message-and-starter-prompts) to match the help your agent provides.

For file uploads, choose a model that supports the type of input your visitors need. The agent’s ability to read an image or document depends on its model and supported inputs. Uploads are also hidden when a visitor turns off conversation history or cannot currently use the chat. The separate chat-link page has no attachment control, even when this switch is on.

## Choose the conversation shortcut

In **Conversation Management**, turn on **Conversations in nav bar** if you want returning visitors to have a direct shortcut to their conversation list. With it off, they can still open **Account → View conversations**.

The creator settings show **Conversation history — Always on**, but visitors have their own **Conversation history** preference in Account. A visitor who turns it off uses a temporary conversation whose messages are not saved and cannot attach files. Hiding the navigation shortcut does not change that preference or delete existing history.

## Save the ordinary feature choices

Set the switches you want, then scroll back to the top of the Design controls and select **Save Changes**. Wait for **All Changes Saved**. If you were in small-screen Preview, return to **Design** to save.

Reopen the same agent from Home and check that the switches kept their saved values. You can inspect the opening questions and navigation in the preview. When the agent is already shared, also check the widget on the published website.

The preview can show unsaved changes. It also does not display actual answer-feedback controls, so use the saved **Answer feedback** switch to check that choice rather than expecting a rating to appear in the preview.

## Decide separately about retained visitor files

**Visitor file drop bucket** keeps a shared copy of visitor uploads in a special Library folder after visitors are told about the sharing. Leave it off unless you need those retained copies. Allowing an attachment for a conversation and retaining a copy for yourself are separate choices.

Changing this toggle saves immediately through its own action; it does not wait for **Save Changes**. Reopen the same agent's Design controls and check the toggle to confirm the stored choice. Files retained this way do not automatically become the agent's general knowledge.

The [visitor file guide](/widget-visitors/files-visitors-send-you) explains the visitor's upload and sharing experience.

## If the expected control does not appear

For missing opening questions, check both **Starter prompts** in Design and the written questions in Build settings. For a missing Conversations shortcut, check **Conversations in nav bar**; the visitor can still use **Account → View conversations**.

For a missing attachment control, check the saved **File upload** switch, whether the visitor's conversation history is on, and whether they are using the website widget rather than the separate chat link. If an attempted upload reports an error, use its actual message to guide the next step.

If an ordinary Design save fails, keep the editor open, read the error and retry **Save Changes** when available. Reopen the agent to verify the stored switches after saving.
