Use these terms to understand how an agent's setup, knowledge and visitor chat fit together. [Home](https://app.alysium.ai/spaces) opens your current space, where you choose an agent to work on.

## Account, space and agent

Your **account** is your sign-in identity. A **space** holds agents, reusable knowledge, the space's plan and its usage allowance. An **agent** is an AI assistant configured for a particular job.

For example, you can open your space and build a café information agent inside it. That agent has its own setup, but shares the space's plan and storage allowance.

## Instructions and prompt

**Agent Instructions** describe the agent's job, audience, answer style and limits. In this context, **prompt** can mean those instructions. In a conversation, a prompt can also mean the request someone sends to the agent.

For a café helper, the instructions might say to answer briefly from the café FAQ and refer booking changes to a staff member. The FAQ supplies the facts; the instructions explain how to use them. Describing an action, such as changing a booking, does not give the agent a way to perform it.

## Knowledge and source

**Knowledge** is reference material you give an agent: documents, pasted text or saved website content. A **source** is one item of that material.

A stored file must be attached to the intended agent and **Ready** before it can supply knowledge answers. Website content has a separate scan-and-save process. Adding a source gives the agent material to consult; you still need to check its replies against that material.

## Library, folder and attachment

[Library](https://app.alysium.ai/library) stores reusable knowledge. **Projects** and **folders** organize it. An **attachment** connects material to an agent: a file attachment covers that file, while a folder or project attachment covers its eligible contents, including later additions.

Saving a file in Library does not attach it to every agent. Choose a folder or project attachment when all the covered material belongs in that agent's knowledge. You can [attach existing Library material without uploading it again](/knowledge-and-library/use-library-files-in-an-agent).

## Model and fine tuning

The **AI model** produces the agent's replies. In Build settings, **AI Models** lets you choose an available model. If the picker says **Select a model...**, open it and choose one; a model name should then appear.

**Fine Tuning Settings** or **Fine Tune Agent** refers to response settings, such as answer length and wording variation. These controls adjust how the selected model responds; they do not train a new model or add reference facts.

## Welcome message and starter prompt

A **Welcome Message** greets someone opening the chat. **Suggested Conversation Starters** are requests a visitor can select to begin. **Agent Instructions** tell the agent how to respond.

For example, a café welcome might invite menu questions, a starter might ask about accessibility, and the instructions tell the agent to answer from the FAQ.

## Preview and saved change

A **preview** lets you see or try a setup while editing. Build's chat preview generates real replies and uses the space's credits. Design's appearance preview can show edits before they are saved.

Build fields generally save automatically after valid edits, with some controls saving when you leave the field. Design uses **Save Changes**; **All Changes Saved** confirms completion. Check the control's save result before leaving rather than treating its preview as confirmation.

## Widget, embed and direct link

A **widget** is visitor chat on a website. **Embedding** means installing the generated code on that website. A **direct link** opens standalone chat without needing your own website.

An agent can have more than one delivery method, with separate settings for each. Designing the chat's appearance and installing it on a website are separate tasks.

## Draft, published, public and live

A **draft** is an agent you are preparing. **Published** is its publication status; **Public access** controls public availability. The launch card shows **Live** when the agent has its required name and instructions, is Published and has Public access on.

A delivery method can have an additional setting, such as **Direct link** for standalone chat. Saving the agent's instructions does not publish it, and making it live does not create an AgentHub listing or paid offer.

## Plan, credits and agent subscription

A **plan** belongs to a space. **Credits** measure AI usage, so they do not represent a fixed number of messages. An **agent subscription** is a separate purchase for access to a creator's paid agent, with its own price and included usage bundle.

**Overages**, shown as **On-Demand Usage**, are paid AI usage beyond an allowance, subject to the space's saved settings. They do not increase file storage. In [Billing](https://app.alysium.ai/spaces?settings=billing), check whether you are viewing the space plan or an individual agent subscription before changing a purchase.

## Owner and permissions

The **owner** controls the space. Spaces currently contain only their owner; invitations and member-role changes are unavailable.

Permission to chat with an agent is separate from permission to edit it or inspect other people's conversations. [Conversation visibility depends on the chat and Analytics access](/analytics/who-can-see-which-conversations).

You can [put these parts together in a first-agent project](/about-alysium/how-to-get-started), or [find the relevant screen](/help/where-things-are-in-alysium) when you already know what you want to change.
