Arrange reference material in projects and folders so you can find it and choose deliberately what an agent should use. Projects group work, folders organize related material, and files hold the reference information.

Creating, moving or renaming can require permission beyond reading an item. You need permission for the operation you want to perform.

Open [Library](https://app.alysium.ai/library) to work with your current space's material. If asked to sign in, sign in and open Library again if needed. Use the projects rail to open the project you want to organize.

For a fictional **Customer help** project, you might keep **Approved FAQ** and **Draft material** in separate folders. Those are example names you create. Keeping them separate helps you attach approved material without including drafts.

## Create a project

1. Select **New project** in the projects rail.
2. Enter a meaningful name in the creation dialog.
3. Select **Create**.
4. Check that the new project appears.

A blank name leaves Create unavailable.

## Create a folder

1. Open the intended project or parent folder.
2. Select **Add new**.
3. Select **New folder**.
4. Enter a meaningful **Folder name**.
5. Select **Create**.
6. Check the folder in that location.

Inside the destination, **Add new** also offers **Upload files**, **Paste text** and the available website source. Uploading a complete folder is not currently supported. Use [Upload files to your agent](/knowledge-and-library/upload-files-to-your-agent) for the document procedure.

## Rename an item

1. Open the item's menu.
2. Select **Rename** where offered.
3. Enter the new name.
4. Select **Save**.
5. Check the saved name.

Renaming changes how you identify the item. It does not rewrite its contents. Check the result before relying on that name in an agent's instructions.

## Move files or folders

Moving material can change an agent's knowledge scope when it has a whole folder or project attached. Check the source and destination before moving an approved file into or out of such a container.

1. Select the item's **Move** action.
2. Choose the destination in the move dialog.
3. Select **Move here**.
4. Open the destination to check the result.

For several items, select them first. Use the bulk **Move** action, then continue from the destination choice in step 2 above.

A destination can be unavailable because it is protected or the move is invalid.

## Read folder and project deletion scope

Deleting a file and deleting a containing folder or project have different scope. A structural deletion can affect descendant items and show a count-based confirmation. Read its explanation of saved files and agent access before confirming.

The default **General** project and special website or visitor-upload folders have restrictions. Deleting a container is not a shortcut for removing one agent's knowledge attachment. Use [Remove a file from your agent](/knowledge-and-library/remove-a-file-from-your-agent) for that task.

If a deletion confirmation says the contents changed, review the updated counts before deciding again. If a file was moved to Trash, use [Restore or permanently delete from Trash](/knowledge-and-library/restore-or-permanently-delete-from-trash) for recovery or permanent erasure.

## If a change fails or a file is missing

Check the actual location and the permission message before repeating a failed create, move or rename. A failed action is not confirmation that the item changed.

Use [Find files in your Library](/knowledge-and-library/find-files-in-your-library) and check Trash when material seems missing. Once the structure is ready, use [Use Library files in an agent](/knowledge-and-library/use-library-files-in-an-agent) to attach the intended file, folder or project.
