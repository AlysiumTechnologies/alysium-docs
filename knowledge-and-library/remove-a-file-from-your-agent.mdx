Remove an attachment when you want to change the sources one agent can use. The file, folder or project stays in Library; its saved files continue to use storage. Other agents keep their own attachments to it.

## Open Attached knowledge

1. Open [Home](https://app.alysium.ai/spaces) and select **Build** on the intended agent's card.
2. In Build, select **Settings** if you are viewing Profile or Chat Preview.
3. Scroll down to **Knowledge** and find **Attached knowledge**.

## Remove the intended attachment

Read the row's name and check whether it is a file, folder or project. Removing a folder or project attachment changes access to its covered material, so choose the smallest scope that matches your goal.

- **For a file:** select its **Remove** control. Removal starts immediately, without a confirmation. Wait for the result; the row disappears after removal succeeds. If removal fails, read the displayed alert and check the attachment before retrying.
- **For a folder or project:** select **Remove** to open **Remove [name]?**. Read the covered-file count and check the agent named in the confirmation. Select **Remove** to confirm, or **Cancel** to keep the attachment. Wait for the result message. The row can disappear while the request is still running; if the action is refused, it returns with an error message.

Removal saves through the action itself. Reopen the agent's Build settings and check **Attached knowledge** to confirm the intended attachment is gone. For a failed folder or project removal, use the displayed reason and the current row state before trying again.

## Check other routes to the same file

A file can reach an agent through more than one attachment. For example, removing a directly attached FAQ still leaves it available if the agent also has the FAQ's folder attached. Review the remaining file, folder and project rows before treating access to that file as removed.

Earlier replies can still contain facts quoted from the source. Check the attachments to confirm the change; an old answer does not show which sources the agent can currently use.

If you removed the wrong attachment, select **Add from Library** in Knowledge. Expand the source's project and folder, select the intended file, folder or project, and select **Attach**. Wait for the result and check its row in **Attached knowledge**. A file should reach **Ready** before you use it for a source question; a folder or project's **Live** label describes its ongoing scope. You can [review how Library attachments work](/knowledge-and-library/use-library-files-in-an-agent) when choosing that scope.

## When you need a broader action

Moving a file to Trash leaves existing agent access in place. In [Trash](https://app.alysium.ai/library?view=trash), **Remove from agents** removes the file's remaining access across agents in your space while leaving it retained. **Delete forever** requests permanent erasure; storage is released when erasure completes.

The [Trash recovery and deletion guide](/knowledge-and-library/restore-or-permanently-delete-from-trash) explains those broader actions, including held files and deletion work still finishing. Use them when your goal concerns the saved file rather than one selected attachment.

If removal keeps failing, email [Alysium support](mailto:support@alysium.ai) with the agent name, attachment name, action and exact message shown.
