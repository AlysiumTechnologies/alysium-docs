Remove an attachment when one agent should stop using a saved file, folder or project. Detaching it leaves the underlying material in Library. It does not delete earlier replies or remove another agent's attachment.

You need editing access to the intended agent.

Decide whether you want to change one agent's knowledge or remove the saved document itself. This guide starts with the one-agent action. [Trash controls](#when-you-need-a-broader-action) have different scope.

**Already at Attached knowledge?** Continue with [Remove the intended attachment](#remove-the-intended-attachment).

## Open Attached knowledge

1. Open [Home](https://app.alysium.ai/spaces).
2. Select the intended agent.
3. Open **Build**.
4. Open **Settings**.
5. Find **Knowledge**.
6. Find **Attached knowledge**.
7. Continue with [Remove the intended attachment](#remove-the-intended-attachment).

Home opens your active space, where you choose the agent. If it asks you to sign in, sign in. Open Home again if needed.

## Remove the intended attachment

Read the name and identify whether the row is a file, folder or project. A file removal acts directly. A folder or project removal covers more material and asks for confirmation.

For example, if a fictional shop FAQ agent was accidentally given a **Draft promotions** folder, detach that folder from the agent. You do not need to delete the folder's documents.

1. Find the intended row in **Attached knowledge**.
2. Select its **Remove** control.
3. If a folder or project confirmation appears, read the scope of covered material.
4. If a confirmation is shown, select **Remove** only when its scope is correct.
5. Check that the attachment is no longer listed.

If the action fails, check the row's actual state and read the error before retrying.

## Check other routes to the same file

The file, folder or project remains saved in Library after detachment. If the same file is also covered by another attached folder or project, that remaining attachment can still supply it. Review the other attachments before assuming the agent has no route to the material.

Earlier replies can still contain facts quoted from the source. Ask a new question to check the current setup; an old reply is not proof that the source remains attached.

If you removed the wrong attachment, follow [Use Library files in an agent](/knowledge-and-library/use-library-files-in-an-agent) to reattach the saved material with **Add from Library**.

## When you need a broader action

Moving a file to Trash does not itself stop agents using it.

| Action | Scope |
|---|---|
| Remove a row from one agent's **Attached knowledge** | Removes that attachment from that agent. The saved source and other attachments remain. |
| **Remove from agents** in **Library → Trash** | Removes the file's remaining access through agents. The file can remain saved or retained. |
| **Delete forever** in Trash | Requests permanent erasure of the saved file. Holds or pending work can affect completion. |

Use [Restore or permanently delete from Trash](/knowledge-and-library/restore-or-permanently-delete-from-trash) when your task concerns the saved document itself. Choose the intended scope before taking a deletion action.
