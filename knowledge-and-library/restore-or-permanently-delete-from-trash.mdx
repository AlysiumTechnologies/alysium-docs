<span id="restore-or-permanently-delete-from-trash" />

Use Trash to recover a saved file, remove its remaining use by agents or request permanent erasure. Each action has a different result.

| Your goal | Action |
|---|---|
| Bring a saved file back into Library | **Restore** |
| Stop agents using a file that remains retained | **Remove from agents** |
| Permanently erase selected files | **Delete forever** |
| Request permanent erasure across the whole Trash | **Empty Trash** |

## Open Trash

Open [Trash](https://app.alysium.ai/library?view=trash) and find the intended file by name. If Library's left navigation is visible, you can also select **Trash** there.

Read the file's retention and hold notes, and any **Still knowledge for** disclosure naming agents. Files are normally kept for **30 days** before automatic deletion, but a hold or pending deletion can keep them longer. Trashed files continue to use storage. Agents with existing access can still use them until that access is removed or erasure completes.

## Restore a file

1. Select **Restore** on the intended file's row. To restore several files together, select their checkboxes and choose **Restore**.
2. Wait for the result and read any notice about the restore location.
3. Open [Library](https://app.alysium.ai/library) and check that the file is present in that location.

Restoring recovers the saved file. Its surviving location is kept where possible. If its folder or project was deleted, the file may be in the surviving project's root or in **General**; follow the location reported by the result. Permanently erased files cannot be restored from Trash.

## Stop remaining use by agents

Use **Remove from agents** when the trashed file should stop supplying knowledge across agents in your space. For a change to just one agent's attachment, [remove it in that agent's Build settings](/knowledge-and-library/remove-a-file-from-your-agent).

1. Find **Still knowledge for** on the intended file's Trash row and select **Remove from agents**.
2. Wait for the action to finish and read the result.
3. Check the refreshed row. If **Still knowledge for** remains, access has not been fully removed.

This action removes direct attachments and takes the file out of folders or projects that supplied it to agents. Read the result's restore-location guidance. Putting the restored file back into an attached folder or project can make it available to agents again. The retained file still uses storage after agent access is removed.

If you see **The document changed before the command completed. Refresh and try again.**, refresh Trash and check the current **Still knowledge for** disclosure before retrying. If the same message persists, email [Alysium support](mailto:support@alysium.ai) with the filename, **Remove from agents** action and exact message. Treat the current disclosure as the access check while the problem remains unresolved.

## Request permanent deletion

Completed erasure is irreversible. Before confirming, check the filenames and scope. A retained or held file can remain after a request, and deletion work may still be finishing. Storage is released when erasure actually completes.

For selected files:

1. Select **Delete forever** on the intended row, or select several files' checkboxes and choose **Delete forever**.
2. Read the **Delete forever?** confirmation. Select **Delete forever** if you want permanent erasure, or **Cancel** to keep the material.
3. Wait for the request's result, then check any remaining files and their notes. The confirmation closing does not establish that erasure finished.

For the whole Trash, select **Empty Trash**, read its confirmation and select **Empty Trash** to request erasure of that scope. Use **Cancel** if you do not want to proceed. Wait for its result and check what remains.

Follow the returned status:

- **Deletion completed:** the erased files cannot be recovered from Trash. Their storage has been released.
- **A file is retained or held:** read the stated reason. Repeating the request does not remove a hold.
- **Some deletions are still finishing and will retry automatically:** let that work continue, then check Trash again. The message does not give a completion time.
- **More files remain in Trash. Run Empty Trash again to continue.** Run **Empty Trash** again to process the next portion, reviewing its confirmation and result each time.

For an unresolved deletion failure, email [Alysium support](mailto:support@alysium.ai) with the filename, displayed state, action and result. You can [check the storage allowance](/knowledge-and-library/storage-limits) before retrying an upload once erasure has completed.
