Use Trash to recover a deleted Library document, stop its remaining use by agents or request permanent erasure. These are separate outcomes.

| Your goal | Action |
|---|---|
| Recover a saved document | **Restore**. |
| Stop the file supplying knowledge while it remains retained | **Remove from agents**. |
| Erase selected files permanently | **Delete forever**. |
| Request erasure across the whole Trash | **Empty Trash**, available to the space owner. |

You need permission for the affected files. Read the item's retention, agent-use and hold information before choosing a permanent action. Permanently erased files have no Trash restore action.

**Already in Trash?** Continue with the action you need: [Restore a file](#restore-a-file), [Stop remaining use by agents](#stop-remaining-use-by-agents) or [Request permanent deletion](#request-permanent-deletion).

## Open Trash

1. Open [Library](https://app.alysium.ai/library).
2. Open **Trash**.
3. Find the intended document by name.
4. Read its retention, agent-use and hold notes.

Library opens your current space's material. If it asks you to sign in, sign in. Open Library again if needed.

Files are normally kept for 30 days before automatic deletion. They use storage while retained. A hold can keep a file beyond that ordinary window.

## Restore a file

1. Find the file in **Trash**.
2. Select **Restore**.
3. Return to the normal Library view.
4. Check that the file is present where it can be used.

For an accidentally deleted FAQ, restore the saved document instead of immediately creating a differently named copy. Restore is a recovery action, rather than another upload.

## Stop remaining use by agents

Moving a file to Trash does not stop agents that still have access to it. The Trash row can disclose that use and offer **Remove from agents**.

This is broader than detaching a row from just one agent. Use [Remove a file from your agent](/knowledge-and-library/remove-a-file-from-your-agent) for the narrower action.

1. Select **Remove from agents** on the intended file's row.
2. Wait for the action to finish.
3. Read the result notice.
4. Check the refreshed Trash row: **Still knowledge for** should no longer appear when no agent uses that file.

The result can confirm that the file will no longer reach your agents and stays in Trash, or that it was not used by any agent. Read any additional guidance about where the file will be placed if you restore it later. Removing agent access leaves the file retained, so it continues to use storage until erased.

If the action fails or the result names a refused file, read the reason. Check the current agent-use notice before treating removal as complete. If **Still knowledge for** remains on a refreshed row, access has not been fully removed. Address the stated reason before retrying, or use [Get help from a person](/help/get-help-from-a-person) if you cannot resolve it.

Old replies are not rewritten when source access changes. Do not use the disappearance of an earlier answer as the test of whether future access was removed.

## Request permanent deletion

A file retained for a stated reason can remain after the request, and deletion work can be pending. Storage is released when erasure actually completes.

1. Select the intended file or files in **Trash**.
2. Select **Delete forever**.
3. Read the confirmation and its scope.
4. Confirm if you intend permanent erasure.
5. Review the result and any items that remain.

For the whole Trash, the space owner can use **Empty Trash** instead. Read its confirmation and review its result just as carefully. Opening a confirmation does not complete erasure.

If a file remains, read the explanation. Repeatedly selecting Empty Trash does not resolve a hold. If the wrong file was only trashed, Restore may still help; after permanent erasure, it cannot.

Use [Storage limits](/knowledge-and-library/storage-limits) to check the allowance and confirm that completed erasure made room before retrying an upload.
