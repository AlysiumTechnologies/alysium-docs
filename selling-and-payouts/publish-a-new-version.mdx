<span id="publish-a-new-version" />

Publish a permanent snapshot of your agent's saved instructions, model, settings and presentation, with release notes explaining what changed. The new version becomes available to buyers without a version-review step. Existing buyers keep their current version until they choose to update.

## Prepare the update

Finish the changes in the source agent's builder and wait for saving to finish. Publishing uses the saved setup. Try the changed behavior before releasing it; you can [plan a broader set of preview checks](/build-your-agent/test-your-agent-while-you-build), using requests that each contain the context the agent needs.

A version preserves configuration, rather than freezing every future answer. The source agent's current reference knowledge can still affect answers for buyers using a managed copy.

## Open version publication

1. Open [Home](https://app.alysium.ai/spaces) and select the source agent you changed.
2. Select **Deploy**, then **Share & Sell**.
3. Scroll below the selling setup dashboard to **Version History** and select **Publish New Version**.

## Publish the snapshot

Read the permanent-snapshot note, then enter release notes in **What's new in this version?**. Describe changes you actually saved. For example:

> Clarified which booking requests the assistant should pass to the café team and shortened its replies.

Select **Publish Version** and wait for publishing to finish. The button shows **Publishing...** during the action. You can use **Cancel** before publishing to leave the dialog.

When publication succeeds, the dialog closes and Version History refreshes. Find the new **v** number, its **active** status, publication date and release notes. That entry is the completion check; existing buyers choosing whether to update is a separate step.

## Check the separate listing state

Version publication and AgentHub storefront review are separate. **AgentHub review pending** can appear while published versions are already available to buyers.

If you also changed the storefront offer or discovery copy, check the **AgentHub** card above Version History and use its offered update or submission action. You can [review the listing details and storefront requirements](/selling-and-payouts/list-your-agent-on-agenthub) separately from the version snapshot.

<span id="if-publish-version-is-unavailable-or-fails" />

## If publishing does not finish

**Publish Version** needs nonblank release notes. If you see **Failed to publish version. Please try again.**, keep your notes and reopen Version History to check whether the snapshot was created before retrying. Also check that the intended source edits saved.

Do not publish another version just to test whether the first succeeded. A published snapshot is permanent; closing its dialog afterward does not undo it.
