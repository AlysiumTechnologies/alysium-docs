Publishing lets people use the agent you have built. Use this guide after trying the agent in the builder, when you are ready to offer it through a public link or website widget. Use an agent whose builder you can edit.

## Before you launch

Give the agent a name and fill **Agent Instructions** in **Build → Settings**. Instructions tell it its role and how to help. Add knowledge if it needs your own facts; readiness to publish does not mean those facts have been added.

For a fictional practice café assistant, ask about a fact you supplied and then a fact you left out. Review **Welcome Message** in **Build → Settings**, then review visitor appearance in **Design**. Replace fictional practice information before offering the agent to customers.

Use [Test your agent while you build](/build-your-agent/test-your-agent-while-you-build) if you still need to check its answers.

**Already on Deploy?** Continue with [Check readiness](#check-readiness).

## Open the launch controls

1. Open [Home](https://app.alysium.ai/spaces).
2. Select the intended agent.
3. Open **Deploy**.
4. Continue with [Check readiness](#check-readiness).

Home opens your active space, where you choose the agent. If it asks you to sign in, sign in. Open Home again if needed. On a narrow screen, the builder's main tabs may appear along the bottom.

## Check readiness

Read the launch card before publishing:

- **Draft** means the agent is not currently published.
- **Ready to go live** means the required fields are present.

If the card already shows **Live**, this launch task is complete. Continue with [Choose where people will open it](#choose-where-people-will-open-it).

If **Finish in Build** lists something missing:

1. Select **Build**.
2. Fill in each missing item.
3. Wait for the builder to finish saving.
4. Return to **Deploy**.

Once the required fields are present, continue with [Make the agent available](#make-the-agent-available).

## Make the agent available

1. Select **Make agent live**.
2. Wait for the action to finish.
3. Check that the launch card shows **Live**.

The make-live action publishes the agent and enables public access together. There is no separate final Save button.

This launch task is complete when the card shows the saved Live state. Distribution is the next task: finish one of the sharing guides below before sending a link or relying on an installed widget.

## Choose where people will open it

| Method | Continue with |
|---|---|
| **Share link + QR** | [Share your agent with a link and QR code](/share-and-deploy/share-your-agent-with-a-link-and-qr-code). A standalone address also needs **Direct link** on. |
| **Embed on a website** | [Put your agent on your website](/share-and-deploy/put-your-agent-on-your-website). You need permission to edit and publish that website. |
| **Share & Sell** | [List your agent on Agenthub](/selling-and-payouts/list-your-agent-on-agenthub), which has separate requirements. |

Going live does not create an AgentHub listing. Use the actual link or installed widget to check the destination when you finish its sharing guide.

## Understand Launch settings

Expand **Launch settings** when you need the individual controls. **Development status** describes whether the agent is Draft or Published. **Publish only** changes that status; it does not by itself enable public access.

**Public access** controls whether external share links and website embeds can be used. The button is **Enable public access** or **Make private**, depending on the current state. A published agent with public access off is not a live public experience.

## If the status or link is not ready

If the button is disabled, resolve the missing requirements or wait for a pending save. If saving fails, read the error and retry; do not assume the status changed.

If a public link is missing despite Live, check **Direct link** under **Share link + QR**. Continue with [Share your agent with a link and QR code](/share-and-deploy/share-your-agent-with-a-link-and-qr-code) to save that setting and check the real destination.
