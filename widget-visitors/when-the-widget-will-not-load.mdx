<span id="when-the-widget-will-not-load" />

A website widget can appear as a floating chat button, a chat box within the page or a full-page chat. If the expected chat does not appear or will not connect, the checks depend on whether you are visiting the website or managing its agent.

<span id="check-as-a-visitor" />

## If you are visiting the website

1. Reload the page. If it has a chat button, select it to open the widget.
2. Read any message in the chat. Select **Retry** if the message offers it.
3. If the problem continues, try the same page in another browser.

If it works in one browser, check whether the other browser's privacy tools or your network settings are blocking the chat. On a managed device, its administrator may need to help.

For a missing widget or an **Access Denied** message, contact the website owner. Send them the page address, the message you saw and whether it also happened in the other browser. They can check the agent's availability and website settings.

<span id="check-public-availability" />

## Check that your agent is live

If you manage the agent, open [Home](https://app.alysium.ai/spaces), select it and open **Deploy**.

The launch card shows **Live** when the agent has its required name and instructions, is published and has public access enabled. If it is not Live:

1. Complete any requirements listed under **Finish in Build**. In **Build**, fill in the missing **Agent Name** or **Agent Instructions**, wait for your changes to save, then return to **Deploy**.
2. If **Make agent live** is still shown after completing the requirements, select it. The card can say **Ready to go live** or **Needs attention** before this action. Making it live publishes the agent and enables public access together.
3. Wait for the card to show **Live**. If the save fails, use the displayed error to retry and check the resulting status.

For an agent that is already Published with public access off, you can also expand **Launch settings** and select **Enable public access**. The [launch guide](/share-and-deploy/make-your-agent-live) explains these controls in more detail.

The **Direct link** switch controls the standalone chat page. Website embedding has its own settings under **Embed on a website**.

<span id="check-website-installation" />

## Check the website installation

With the agent Live, select **Embed on a website** in Deploy.

1. Wait for its saved settings to load. If you see **Website settings could not be loaded**, select **Retry** before copying code or changing the website restrictions.
2. Select **Copy code**. **Copied!** confirms the copy. If copying fails, retry or select the displayed code and copy it manually.
3. In your website editor's custom-code or script facility, replace the old Alysium snippet with the code you copied. If the widget has not been installed yet, add the code once. Place it before the closing body tag where the editor supports that placement. If someone else manages the website, give them the generated code to update or install.
4. Save and publish the website change, then open the published page and check that the intended agent appears and connects.

Use the code generated for this agent and its chosen placement. An inline chat appears within the page rather than behind a floating button. The [website installation guide](/share-and-deploy/put-your-agent-on-your-website) has more detail about placing the code.

<span id="check-allowed-websites" />

## Check a website restriction

If the widget says the website is blocked, find **Allowed websites** under **Deploy**, within **Embed on a website**.

Restrictions apply when the switch shows **Restricted** and the list contains at least one saved website. Compare those entries with the hostname in the published page's address. For example, the hostname in `https://www.example.com/help` is `www.example.com`; `www` and other subdomains matter.

To allow another hostname while keeping your restrictions:

1. Turn on the switch beside **Any website** if it is off. Its label changes to **Restricted**, revealing the **Add a website** field.
2. Enter the hostname, such as `www.example.com`, without `https://` or a page path.
3. Select **Add website** and wait for it to appear in the saved list. Correct any displayed validation error before trying again.
4. Reload the published page and open the chat again.

These changes save automatically. Check the saved list after an error; text left in the input has not been added. An empty list allows all websites, even with restrictions switched on. These restrictions apply to embedded chat; the standalone direct link has separate access controls. You can [allow several subdomains with a wildcard](/share-and-deploy/limit-which-websites-can-show-your-agent) when that fits your website setup.

<span id="prepare-a-useful-report" />

## If you still need help

Visitors should send the website owner the page address and the error they saw. If you manage the agent, email [Alysium support](mailto:support@alysium.ai) with:

- The published page's URL and the agent's name.
- Your browser and device.
- Whether the widget is missing, fails to open or shows an error, including the exact message.
- The checks you tried and what happened.

This gives the person helping you a specific installation and symptom to investigate. Keep passwords and verification codes out of the message.
