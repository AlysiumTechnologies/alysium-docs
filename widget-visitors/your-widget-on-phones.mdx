Check your agent on the phone and page your visitors will use. Try its opening screen, a useful question and the menu so you can see whether people can read and navigate it comfortably.

## Choose the route

| Route | What to open on the phone |
|---|---|
| Website widget | Your published website. Open the chat launcher for a floating widget; an inline or full-page installation may already be visible. |
| Shared chat page | The agent's actual copied direct link, or its QR code. |

To copy your agent's direct link, open [Home](https://app.alysium.ai/spaces), select **Build** on its card, then open **Deploy → Share link + QR**. The agent needs **Published** status and **Public access on**. Turn **Direct link** on, wait for the address to appear, then select **Copy** beside it. **Copied!** confirms the clipboard action. You can [set up the link and QR code](/share-and-deploy/share-your-agent-with-a-link-and-qr-code) if the agent is not ready to share yet.

Check each route you intend to distribute. A working QR destination does not check the widget's installation on your website.

## Try a short phone visit

1. Open the chosen website or shared chat page. Open the launcher if the website uses one.
2. Check the agent's name, greeting and suggested questions.
3. Tap **Chat** to reach the message box. Enter a short, complete question that the information you supplied should answer.
4. Tap the arrow labelled **Send message** and wait for the reply or displayed notice. Selecting a starter question also sends a real message.
5. Read the reply, scroll through the conversation and compare the answer with your source.
6. Open the visitor menu, inspect a destination such as **About This Agent** or **Help & Support**, then return to Chat.

The menu path differs between the two routes:

| Route | Open the menu from Chat |
|---|---|
| Website widget | Tap **Back to browse** in the header, then **Account**. Tap **Chat** in the browse navigation to return. |
| Shared chat page | Tap **Open menu** in the header. **Close menu** closes the drawer. **Back to browse** returns to Home without clearing the conversation. |

On narrow screens, an open floating website widget can fill the available viewing area. Its header's **Close** button returns you to the website.

## Check text, prompts and files

Read the greeting, starter questions and typing hint at normal phone size. Check any external help or policy links you offer. To improve the wording, edit **Welcome Message** and **Suggested Conversation Starters** in **Build → Settings**. Appearance, widget title, typing hint and features are in **Design**; select **Save Changes** and wait for **All Changes Saved** after changing those settings.

For a website widget that offers attachments, check that its attachment action reaches the phone's file picker and that you can read the sharing notice. The [visitor-file guide](/widget-visitors/files-visitors-send-you) explains that task and its privacy choices.

The separate shared chat page currently has no file-upload action, even when **File upload** is enabled in Design. Its **Your uploaded files** menu lets a visitor view or delete files they already own; it is not a place to add another file.

## If the keyboard covers the conversation

Dismiss the keyboard to read, then tap the message box when you want to type again. If the link opened inside another app, try opening it in the phone's normal browser to compare the layout.

If a control remains hidden, contact [Alysium support](mailto:support@alysium.ai) with the device, browser, actual website or chat-page address and the control you cannot reach.

## If the chat does not connect

Follow the action offered by the notice on that route:

- On the shared chat page, a session failure can offer **Try again**. If delivery is uncertain, use **Check for the reply** before sending the question again. **Send it again** is offered when Alysium confirms the request did not start.
- In a website widget, use **Retry** when it is offered and read the resulting message. You can [check widget loading and access problems](/widget-visitors/when-the-widget-will-not-load) if it still cannot connect.

If the shared link is unavailable, reopen the same agent's Deploy settings and check Published status, public access and Direct link. If those settings are on but the page still fails, contact [Alysium support](mailto:support@alysium.ai) with the agent's name, copied link and displayed message.

The phone check is complete when you can identify the intended agent, send and read a useful exchange, and use its navigation on that device. Repeat it for the routes and devices you intend to support.
